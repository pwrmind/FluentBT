# 🔀 FluentBT

**Минималистичный DSL для описания Behavior Trees (деревьев поведения) с реактивным tick-движком.**

Текстовая альтернатива визуальным BT-редакторам: дерево описывается списком правил, компилируется в тиковую машину состояний, исполняется реактивно — с прерыванием текущих действий и перепроверкой условий на каждом тике.

## Что это и зачем

**Behavior Tree (BT)** — это способ организации переключения между задачами автономного агента (робота, NPC, игрового персонажа). В отличие от конечных автоматов (FSM), BT дают **модульность** (поддеревья переиспользуются) и **реактивность** (условия перепроверяются на каждом тике) без комбинаторного взрыва переходов.

Ссылка: Michele Colledanchise, Petter Ögren. [*Behavior Trees in Robotics and AI: An Introduction*](https://arxiv.org/abs/1709.06711). CRC Press, 2018.

**FluentBT** — это DSL, который позволяет описывать BT **текстом** вместо визуального редактора. Он не пытается быть универсальным BT-фреймворком — он компактен, расширяем и пригоден для встраивания в игры, симуляторы и прототипы роботов.

### Три идеи, на которых всё построено

1. **Priority-list guard rules.** Программа — это приоритетный Fallback групп. Группа с заголовком `[C]` — это `Sequence(C, Fallback(rules))`. Первая сработавшая группа останавливает выполнение.

2. **Три статуса, один tick-loop.** Каждый блок возвращает `SUCCESS` / `FAILURE` / `RUNNING`. Дерево тикается сверху вниз; `RUNNING` приостанавливает нижележащие правила; `abort` вызывается при преемпции.

3. **`retry` без параметра = persist.** «Пробуй действие, пока не получится» — это не отдельный узел, а `retry:∞`. Он возвращает `RUNNING` родителю на `FAILURE` ребёнка. Решение «тикать снова» принадлежит дереву, а не листу — поэтому бинарное действие (`SUCCESS`/`FAILURE`) достаточно для длительных процессов.

## Быстрый старт

FluentBT — это один HTML-файл. Откройте `index.html` в браузере, и увидите три демо-сценария во вкладках.

### Hello World

```
[ВрагРядом]
[Атаковать]
```

Одна группа: если `ВрагРядом` — выполнить `Атаковать`. Если нет — вернуть `FAILURE`.

### Hello World с fallback

```
[ВрагРядом]
[Атаковать]

[Голоден]
[Поесть]
```

Две группы. Если `ВрагРядом` — атака. Иначе если `Голоден` — еда. Иначе — провал.

### Длительное действие через `retry`

```
[Голоден]
[ЕстьЕда] [Поесть] [retry [Охота]]
```

`Охота` возвращает `FAILURE` пока не готова, `SUCCESS` когда готова. `retry` без параметра превращает `FAILURE` в `RUNNING` и тикает её снова в следующем цикле. `ЕстьЕда` — guard: если еда есть, идём в `Поесть`, иначе — в `Охота`.

## Спецификация языка

### Лексика

```
line        := statement ("//" comment)?
statement   := block+
block       := "[" (atom | combinator | decorator | nested)* "]"
atom        := идентификатор
duration    := число ("ms" | "s" | "m")?
```

- **Комментарии**: `//` до конца строки.
- **Пустые строки** игнорируются.
- **Скобки** `[` и `]` балансируются рекурсивно; блоки верхнего уровня извлекаются парсером.
- **Одна строка** содержит 1, 2 или 3 блока верхнего уровня. Больше — ошибка парсинга.

### Блоки (выражения)

| Блок | Аналог в BT | Что делает |
|---|---|---|
| `Идентификатор` | Action или Condition | Вызов из регистра; статус зависит от типа |
| `not X` | Invert Decorator | `SUCCESS` ↔ `FAILURE`, `RUNNING` пропагируется |
| `all X₁ … Xₙ` | Sequence (`→`) | Первый `FAILURE`/`RUNNING` — наверх; `SUCCESS` если все `SUCCESS` |
| `any X₁ … Xₙ` | Fallback (`?`) | Первый `SUCCESS`/`RUNNING` — наверх; `FAILURE` если все `FAILURE` |
| `retry X` | `retry:∞ X` (persist) | На `FAILURE` — `RUNNING`; на `SUCCESS` — `SUCCESS` |
| `retry:N X` | MaxNTries | До N попыток; между попытками `RUNNING`; после N — `FAILURE` |
| `repeat X` | `repeat:∞ X` | На `SUCCESS` — `RUNNING`; на `FAILURE` — `FAILURE` |
| `repeat:N X` | Repeat-N | Требует N последовательных `SUCCESS` |
| `wait:T X` | Delay | `RUNNING` в течение T секунд, затем тикается X |
| `timeout:T X` | MaxTSec | Тикает X, но после T секунд — `FAILURE` |

**Длительности**: `100ms`, `2s`, `1m`, или просто число (секунды).

**Терминальные идентификаторы** ищутся в регистре (`reg`). Если не найдены — ошибка компиляции.

### Строки программы

Строка верхнего уровня — это правило или заголовок группы.

| Форма | Компилируется в | Возвращает |
|---|---|---|
| `[C]` (1 блок, `C` — условие) | **Новая группа** с заголовком `C` | Вход в группу если `C` = `SUCCESS`; иначе группа = `FAILURE` (провал в следующую) |
| `[A]` (1 блок, `A` — действие) | **Безусловное правило** в текущей группе | `SUCCESS` / `FAILURE` / `RUNNING` — статус `A` |
| `[C] [A]` (2 блока) | `Sequence(C, A)` — правило в текущей группе | `C` = `FAILURE` → `FAILURE` (к следующему правилу); `C` = `SUCCESS` → статус `A` |
| `[C] [A₁] [A₂]` (3 блока) | `Fallback(Sequence(C, A₁), A₂)` — правило; **закрывает группу** | `C` = `SUCCESS` → статус `A₁`; `C` = `FAILURE` → статус `A₂` |

**Ключевое правило**: строка `[C]` (1 блок, где `C` — условие) **всегда открывает новую группу**. Всё, что идёт ниже до следующей такой строки или до 3-блочного правила — принадлежит этой группе.

**Как парсер отличает условие от действия?** Через `isCondition`:
- `not X` — условие, если `X` — условие.
- `all …` / `any …` — условие, если все дети — условия.
- `retry …` / `repeat …` / `wait …` / `timeout …` — условие, если внутренний блок — условие.
- `Идентификатор` — условие, если `reg[Идентификатор].type === 'condition'`.

Действия (даже если возвращают `SUCCESS`/`FAILURE`) **всегда** считаются действиями. Поэтому `[Атаковать]` в начале строки — это безусловное правило, а не заголовок группы.

### Семантика примитивов

#### `all X₁ … Xₙ` (Sequence)

Тикает детей слева направо, останавливается на первом `FAILURE` или `RUNNING`:

```
для i от 1 до n:
    s = eval(Xᵢ)
    если s == FAILURE: вернуть FAILURE
    если s == RUNNING: вернуть RUNNING
вернуть SUCCESS
```

#### `any X₁ … Xₙ` (Fallback)

Тикает слева направо, останавливается на первом `SUCCESS` или `RUNNING`:

```
для i от 1 до n:
    s = eval(Xᵢ)
    если s == SUCCESS: вернуть SUCCESS
    если s == RUNNING: вернуть RUNNING
вернуть FAILURE
```

#### `retry:N X` (MaxNTries)

```
s = eval(X)
если s == SUCCESS: вернуть SUCCESS (счётчик сбросить)
если s == RUNNING: вернуть RUNNING (счётчик не трогать)
если s == FAILURE:
    счётчик++
    если счётчик < N: вернуть RUNNING
    иначе: счётчик сбросить, вернуть FAILURE
```

#### `retry X` = `retry:∞ X` (persist)

```
s = eval(X)
если s == SUCCESS: вернуть SUCCESS
если s == FAILURE: вернуть RUNNING   // ← вся суть
иначе: вернуть s (RUNNING)
```

**Stateless.** Никакого счётчика. Действие может быть бинарным — `retry` сам генерирует `RUNNING`.

Это **persist-паттерн**: «доверяем, что рано или поздно `SUCCESS` придёт».

#### `repeat:N X` (Repeat-N)

```
s = eval(X)
если s == FAILURE: вернуть FAILURE
если s == RUNNING: вернуть RUNNING (счётчик не трогать)
если s == SUCCESS:
    счётчик++
    если счётчик >= N: вернуть SUCCESS (счётчик сбросить)
    иначе: вернуть RUNNING
```

#### `repeat X` = `repeat:∞ X`

```
s = eval(X)
если s == FAILURE: вернуть FAILURE
если s == SUCCESS: вернуть RUNNING   // ← повторяем бесконечно
иначе: вернуть s
```

#### `wait:T X`

- Первый тик: фиксируется дедлайн `now + T`.
- До дедлайна: `RUNNING` (X не тикается).
- После дедлайна: `X` тикается, статус возвращается.

#### `timeout:T X`

- Первый тик: фиксируется дедлайн `now + T`.
- До дедлайна: `X` тикается; на `SUCCESS`/`FAILURE` — наверх, `RUNNING` — наверх.
- После дедлайна: `FAILURE` (X больше не тикается).

### Tick-цикл, статусы, abort

#### Статусы

| | Condition | Action |
|---|---|---|
| **SUCCESS** | если предикат истинен | при успешном завершении |
| **FAILURE** | если предикат ложен | при провале / невозможности |
| **RUNNING** | **никогда** | пока действие выполняется |

`RUNNING` у Condition — запрещён по контракту. Если действие возвращает `RUNNING` — оно попадает в `this.running` с `abort` (если задан).

#### Tick-цикл

```js
tick() {
  visited = new Set()
  result = run(visited)
  // 1. Преемпция Running-действий
  для каждого (id, info) из this.running:
    если id ∉ visited:
      info.abort()  // очистка состояния
      this.running.delete(id)
  // 2. Сброс состояния декораторов
  для каждого id из this.state:
    если id ∉ visited:
      this.state.delete(id)
  return result
}
```

- **`visited`** — множество всех узлов, до которых дошёл тик (включая синтетические, например `parent/retry/child`).
- **`this.running`** — активные Running-действия с `abort`.
- **`this.state`** — состояние `retry:N` / `repeat:N` / `wait` / `timeout` (счётчики, дедлайны).

**Реактивность**: каждый тик начинается с корня. Условия перепроверяются. Если условие изменилось — соответствующее поддерево выбирается или преемптится.

#### abort и преемпция

`abort` вызывается, когда действие **тикалось в предыдущем цикле**, но **не тикается в текущем**. Это происходит, когда:

- Группа с заголовком перестала тикаться (условие `C` стало `FAILURE`).
- Fallback выбрал другую ветку (более приоритетное правило сработало).
- `retry:N` исчерпал попытки.
- `timeout:T` истёк.

`abort` — механизм очистки: сбросить `huntTicks`, отпустить захват, прервать движение, закрыть файл. Действие обязано вернуть мир в чистое состояние.

**Регистрация**: `abort` регистрируется в `this.running` при **любом не-`SUCCESS`** результате действия (а не только при `RUNNING`). Семантика: `SUCCESS` = чистое завершение, `abort` не нужен; `FAILURE` или `RUNNING` = «грязно», `abort` может понадобиться.

## Примеры

### Воин (демонстрация групп и safety)

```
// Safety hoisted (§3.4 книги) — критическое условие выше боевых групп
[all [ЗдоровьеМало] [ВрагРядом]]
[Отступить]

[ВрагОченьБлизко]
[retry:3 [Атаковать]]
[Отступить]

[ВрагРядом]
[not [ВрагОченьБлизко]] [Приблизиться]

[Голоден]
[ЕстьЕда] [Поесть] [retry [Охота]]

[Устал] [Спать] [Блуждать]
```

**Что демонстрирует:**
- Safety-условие (`HP < 30 ∧ D < 15`) вынесено в отдельную группу **выше** боевых — приоритет гарантирован структурой.
- `retry:3` — конечное число попыток атаки.
- `[Отступить]` после атаки — Fallback при провале.
- `retry [Охота]` — persist-паттерн: `Охота` бинарная, `retry` генерирует `RUNNING`.
- `abort` на `Охота` срабатывает, если враг прервал охоту.

### Pac-Man (пример из книги, §1.4, Рис. 1.12)

```
// Fallback( Sequence(GhostClose, Fallback(Sequence(GhostScared, Chase), Avoid)), EatPills )
[ПризракБлизко]
[ПризракИспуган] [ГнатьсяЗаПризраком] [УбегатьОтПризрака]

[СъестьТаблетку]
```

**Что демонстрирует:**
- Прямая реализация Combative Behavior из книги.
- Вложенный `if-then-else` через 3-блочное правило.
- Модульность: `EatPills` переиспользуется как fallback верхнего уровня.

### Манипулятор (пример из книги, §1.5, Рис. 1.16)

```
// Три группы, ноль all/any. Sequence через «переход вниз» (§3.2 implicit sequence).

[ЗеленыйКубНаЦели]
[УжеГотово]

[not [ДержуЗеленыйКуб]]
[КубБлизко] [СхватитьКуб]
[not [КубБлизко]] [ПодойтиККубу]

[ДержуЗеленыйКуб]
[БлизкоКели] [ПоставитьКуб]
[not [БлизкоКели]] [ПодойтиКЦели]
```

**Что демонстрирует:**
- Суб-BT композиция через группы: `Pick` и `Place` — не отдельные узлы, а группы.
- **Implicit sequence** (§3.2): порядок «подойти → схватить → подойти к цели → поставить» гарантирован **взаимоисключающими заголовками групп** (`Держу` / `not Держу`).
- Реактивность: если куб выпал, `[not [ДержуЗеленыйКуб]]` становится `SUCCESS`, программа автоматически переключается на pick-ветку. Строка программы не меняется.
- **Ноль `all`/`any`**: вся структура — в заголовках и правилах. Это «языковой» способ, а не «костыль через комбинаторы».

## Сравнение с классическими BT

| FluentBT | Классический BT (книга) |
|---|---|
| `all X₁ … Xₙ` | Sequence (`→`) |
| `any X₁ … Xₙ` | Fallback (`?`) |
| `not X` | Invert Decorator |
| `retry:N X` | MaxNTries |
| `retry X` | persist / retry-forever |
| `repeat:N X` | Repeat-N |
| `repeat X` | repeat-forever |
| `wait:T X` | Delay |
| `timeout:T X` | MaxTSec |
| `[C]` | Заголовок группы = `Sequence(C, Fallback(rules))` |
| `[C] [A]` | `Sequence(C, A)` |
| `[C] [A₁] [A₂]` | `Fallback(Sequence(C, A₁), A₂)` |
| `[A]` | Безусловное правило |
| Программа = Fallback(groups) | Fallback верхнего уровня |
| `visited` + `running` + `abort` | Реактивное прерывание Running (§1.3.1) |
| `this.state` (retry/wait/timeout) | Память декоратора, сбрасываемая при выходе из поддерева |

### Чего в FluentBT нет (по сравнению с книгой)

- **Parallel** (`≡`, M из N) — только последовательные композиции.
- **Memory-nodes** как отдельного класса (`Sequence*`, `Fallback*`) — память есть только у декораторов (`retry:N`, `repeat:N`, `wait`, `timeout`); `all`/`any` полностью реактивны.
- **Явных узлов дерева** — синтаксис линейный, дерево строится неявно из групп, правил и комбинаторов.
- **Stochastic-параметров** в DSL — вероятности задаются внутри действий (`reg`), не в языке.
- **Utility / Hinted / PA-BT** — не поддерживаются (см. главы 4, 7 книги).

### Что это значит

FluentBT **не** претендует на полноту классической формализации. Это **практический DSL для прототипирования**, покрывающий 90% реальных случаев: последовательности, fallback, условия, длительные действия, таймауты, повторы. Для большинства NPC и роботов этого достаточно.

## Принципы дизайна

### 1. Программа = Fallback групп

Верхний уровень — приоритетный список. Первая сработавшая группа выигрывает. Это Teleo-Reactive-подобная структура (§2.4 книги) и естественный способ выражать приоритеты.

### 2. Группа = Sequence(header, Fallback(rules))

Заголовок — это **guard**. Если guard ложен, группа пропускается. Если истинен, тикаются правила. Первое успешное правило — выигрывает.

### 3. Действия бинарные, RUNNING — в модификаторах

`Action` возвращает `SUCCESS`/`FAILURE`. `retry` и `repeat` генерируют `RUNNING` за него. Решение «тикать снова» — принадлежит дереву, а не листу. Это упрощает Action-API: «получилось / не получилось», без третьего статуса.

Действия **могут** возвращать `RUNNING` напрямую — это опционально и полезно для stateless-действий, которые сами смотрят на мир (например, `Approach Ball`: `RUNNING` пока далеко, `SUCCESS` когда близко).

### 4. Implicit sequence через заголовки групп

`Sequence(A, B)` — это `Fallback(post_B, Sequence(pre_A, A))`. В FluentBT это выражается **взаимоисключающими заголовками групп**:

```
[not [Готово]]      ← pre: не готово
[Действие1]

[Готово]            ← post: готово
[Действие2]
```

Это §3.2 книги: sequence выражается через fallback с предусловиями. Без `all`, без вложенности.

### 5. Safety hoisted

Критическое условие (низкое HP, перегрев, разряд батареи) выносится в **отдельную группу выше** боевых. Это §3.4 книги. Safety гарантируется приоритетом, а не порядком правил внутри группы.

### 6. `abort` — очистка на преемпции

Действие может оставить мир в «грязном» состоянии: захват, движение, таймер. `abort` вызывается, когда дерево переключилось на другую ветку. Действие обязано очистить состояние.

## API регистра

Каждое действие и условие регистрируется объектом:

```js
const reg = {
  "Имя": {
    type: 'condition' | 'action',
    fn: (bb) => Status,           // обязательный
    abort?: (bb) => void          // опциональный, только для actions
  }
};
```

- **`bb`** — blackboard (объект, разделяемый всеми действиями). Хранилище состояния мира.
- **`fn(bb)`** — вызывается на каждом тике. Возвращает `S.SUCCESS`, `S.FAILURE` или `S.RUNNING`.
- **`abort(bb)`** — вызывается при преемпции. Должен очистить состояние действия.

### Контракт Condition

- **Не возвращает `RUNNING`.** Только `SUCCESS` или `FAILURE`.
- Возвращает `SUCCESS`, если предикат истинен, `FAILURE` иначе.

### Контракт Action

- Возвращает любой из трёх статусов.
- `SUCCESS` = задача выполнена, действие завершено.
- `FAILURE` = действие невозможно / провалилось / «ещё не готово» (в паре с `retry`).
- `RUNNING` = действие выполняется, тикать снова.

### Пример

```js
const reg = {
  "ВрагРядом": { type:'condition', fn: (bb) => bb.d < 15 ? S.SUCCESS : S.FAILURE },

  "Охота": {
    type: 'action',
    fn: (bb) => {
      bb.huntTicks = (bb.huntTicks || 0) + 1;
      if (bb.huntTicks < 2) return S.FAILURE;   // «ещё не готово»
      bb.huntTicks = 0;
      bb.hungry = false;
      return S.SUCCESS;
    },
    abort: (bb) => { bb.huntTicks = 0; }
  }
};
```

## Roadmap

### v3 (текущая)

- ✅ Tick-движок с тремя статусами
- ✅ Приоритетный Fallback групп
- ✅ Комбинаторы: `all`, `any`, `not`
- ✅ Декораторы: `retry[:N]`, `repeat[:N]`, `wait:T`, `timeout:T`
- ✅ `retry` без параметра = persist
- ✅ Реактивное прерывание Running-действий
- ✅ `abort` на любом не-`SUCCESS`
- ✅ Симулятор с тремя сценариями (воин, Pac-Man, манипулятор)

### v4 (планируется)

- ⬜ **Parallel (`≡`, M из N)** — по Algorithm 3 книги
- ⬜ **Memory-nodes** — `Sequence*`, `Fallback*` (книга §1.3.2)
- ⬜ **Скомпилированный вывод** — `FluentBT.compile(source)` → pure-JS объект без интерпретатора
- ⬜ **NPM-пакет** — `import { FluentBT } from 'fluentbt'`
- ⬜ **Визуализация дерева** — подсветка активных узлов при тике
- ⬜ **Тесты** — unit-тесты на парсер и семантику

### Не планируется

- ❌ Utility BT, Stochastic BT, Hinted BT — специализированные расширения, не нужны для прототипа
- ❌ PA-BT / ABL — полные планировщики, вне scope
- ❌ Визуальный редактор — текст проще и переносимее
